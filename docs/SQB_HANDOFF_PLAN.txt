T6 — ADMIN ANALYTICS (RECHARTS)                                   STATUS: DONE
                                                       (UI not visually checked)
--------------------------------------------------------------------------------
  BACKEND — NEW endpoint GET /admin/analytics in backend/app.js, placed
  immediately after the existing GET /admin/stats handler.
    * behind adminAuth
    * SEPARATE from /admin/stats on purpose: /admin/stats auto-refreshes every
      2 minutes and already runs ~32 queries; the heavy time-series must not
      ride that loop.
    * ?from=&to= ISO dates, parsed/validated, swapped if reversed, window
      clamped to 365 days, default last 90 days, always parameterised ($1/$2)
    * TIMEZONE: login_time / created_at are TZ-less UTC. Riyadh is a fixed UTC+3
      with no DST, so all day buckets use `(login_time + INTERVAL '3 hours')::date`.
      Without this every daily bucket is wrong by ~3 hours.
    * GAP-FILL: generate_series(from, to, '1 day') LEFT JOIN counts, so
      zero-activity days still appear on the charts.
    * Promise.allSettled for every query, so one failure degrades one section
      instead of 500-ing the whole dashboard.
    Returns: range, accountMix[], totals{}, activeUsers{dau,wau,mau}, logins[],
             signups[], growth[], engagement{}

    ACCOUNT CLASSIFICATION USED (verified against the real schema):
      legacy = grandfathered_at IS NOT NULL OR subscription_status='grandfathered'
      paid   = grandfathered_at IS NULL AND subscription_status='active'
      trial  = grandfathered_at IS NULL AND subscription_status='trial'
      free   = computed remainder, so the pie always sums to total accounts
      conversion = distinct paid payers / trial_grants count, div-by-zero guarded

  FRONTEND
    * npm i recharts (already installed). It code-splits into its own ~285 kB
      chunk and admin routes are lazy, so the public LCP route is unaffected.
    * components/ADD/AdminAnalytics.jsx — NEW, self-contained (own fetch, own

    * components/ADD/AdminAnalytics.css — NEW.
    * components/ADD/Admin.jsx — imports it and renders <AdminAnalytics /> right
      after the quick-actions row. Nothing else in Admin.jsx was changed.

VALIDATE SVGs PARSE, PAINT *AND ARE NOT CLIPPED* (dev-server browser console).
  The older version of this script only checked parse + paint. That is NOT
  enough — it passed 5 figures that were silently cutting off content outside
  their viewBox. Use this version instead; it adds the viewBox containment
  check and should report "problems: NONE".

    (async () => {
      const files=['medicine','pediatrics','obgyn','surgery'];
      const problems=[]; let total=0, ok=0;
      const host=document.createElement('div');
      host.style.cssText='position:fixed;left:-9999px;width:760px';
      document.body.appendChild(host);
      for (const n of files) {
        const txt=await fetch('/src/components/summaries/content/'+n+'.js?t='+Date.now()).then(r=>r.text());
        (txt.match(/<svg[\s\S]*?<\/svg>/g)||[]).forEach((s,i)=>{
          total++;
          if(new DOMParser().parseFromString(s,'image/svg+xml').querySelector('parsererror')){problems.push(n+'#'+i+' MALFORMED');return;}
          host.innerHTML=s;
          const el=host.querySelector('svg');
          const [vx,vy,vw,vh]=el.getAttribute('viewBox').split(/[ ,]+/).map(Number);
          const b=el.getBBox();
          const texts=[...host.querySelectorAll('text')].filter(t=>t.getComputedTextLength()>0).length;
          const worst=Math.max(vx-b.x, vy-b.y, (b.x+b.width)-(vx+vw), (b.y+b.height)-(vy+vh));
          if(worst>1) problems.push(n+'#'+i+' CLIPPED by '+worst.toFixed(1)+'px');
          else if(b.width>50&&b.height>20&&texts>0) ok++;
          else problems.push(n+'#'+i+' BLANK/NO TEXT');
        });
      }
      document.body.removeChild(host);
      return total+' svgs | '+ok+' fully OK | problems: '+(problems.length?'\n'+problems.join('\n'):'NONE');
    })()

  A clip on the RIGHT is fixed by widening the viewBox width. A clip on the
  LEFT (negative bbox.x) needs a NEGATIVE viewBox min-x — usually caused by an
  over-long text-anchor="middle" caption that overhangs both edges.

PART F — SVG LAYOUT DEFECTS: WHAT WENT WRONG AND HOW TO NOT REPEAT IT
================================================================================

WHAT HAPPENED
  Two earlier passes declared all figures "verified". The owner then found
  obvious visual bugs by simply looking at the page: text running out of the
  side of a card, and labels sitting on top of a drawing. Both passes were
  running checks that could not detect either fault.

WHY THE OLD CHECKS MISSED IT
  * "parses + paints"  — an SVG with text spilling out of a coloured box still
    parses fine and still has a valid bounding box. Passes.
  * "viewBox clipping" — text that overflows its CARD but stays inside the
    viewBox is not clipped by the viewBox at all. Passes.
  * "text-vs-text collision" — a label sitting on top of a circle or a rect is
    not overlapping another TEXT node. Passes.
  In short: every check was about the SVG as a whole, and none was about a text
  element versus the box it is supposed to live in.

THE CHECK THAT ACTUALLY WORKS (use this one — it is in PART D)
  For every <text>: if some shape fully contains it → fine. Otherwise, if it
  intersects any shape → flag it. Plus the viewBox containment check.
  Collect shapes from rect, circle, ellipse, path, polygon — NOT just rect and
  circle. The brain outlines in the haematoma figure are <path>, which is
  exactly why an earlier run of this check reported it clean.

KNOWN FALSE POSITIVES (verify by hand before "fixing")
  * A <polyline> bounding box is the box around the whole squiggle, not the
    stroke, so a label sitting in a trough looks like a collision but is not
    (medicine JVP waveform, the "y" label).
  * Text sitting exactly on the boundary between two equal-area quadrant paths
    can pick the "wrong" owner and report a phantom spill (medicine coronary
    territories, the "Lateral" label — measured at a real 5.4px gap).
  Always print the actual numbers before editing coordinates.
