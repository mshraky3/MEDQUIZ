# How new study material enters SQB (checked 2026-11-16)

Written after a 151-file Telegram batch (SMLE specialty decks, weekly recall PDFs, plus lab, nursing and dental
files) was handed over with the instruction "add it to the website". This is the map of what each kind of file
can become with the code that exists today. Nothing here is a plan to publish: copyright and doctor review are
the owner's call.

| Kind of file | Where it can live | Existing mechanism | Status |
|---|---|---|---|
| Recall question compilations (weekly digests, monthly files) | `questions` table, one collection per source key | `backend/scripts/parseOctoberRecallPdfs.py [src_dir] [out_dir]` -> clean JSON -> `POST /admin/import-recall` (dry run by default, admin key) via `services/recallImportService.js`. Dedupes by normalised text and ATTACHES existing rows (`sources` array). A new collection key goes in `config/sources.js`, `utils/sourceLabels.js` and `COLLECTION_META` (`seo/pastPapers.js`). | The parser also reads the November weekly PDFs of the same series (tested on a copy: 657 questions parsed from 5 PDFs, 93 pages held for a human, 283 pages not read: pictures or text without options). Importing is a live write: owner only, after a doctor review. |
| Specialty study notes (SMLE decks, summaries) | In-code lessons: `my-react-app/src/components/summaries/content/<slug>.js` (+ `backend/content/summaryHtml/`, mobile copy via `npm run sync:summaries`), one `summaries` row per deck | Authored HTML sections with figures and questions. | There is **no PDF upload path in use**. |
| Public free library | `my-react-app/src/seo/data/publicQuestions.json` | Generated by `backend/scripts/exportPublicQuestions.js`; never hand-edited. It is a sample of the question bank, not a file shelf. | Not a place for PDFs. |
| Textbooks, paid course bundles | nowhere | none | Copyright: do not host. |

## Why a PDF cannot simply be added as a deck

`backend/scripts/uploadSummaries.js` renders a PDF to per-page WebP images, writes them to private R2 and upserts a
`summaries` row. The server still has `GET /api/summaries/:slug/page/:n` for those images, but **neither the web
app nor the Android app calls it** (checked: no `/page/` or `r2_prefix` use in `my-react-app/src` or `mobile/src`;
both clients render the in-code lessons). A deck uploaded that way would be a database row nobody can open, and
the script writes to live R2 and the live database with `is_published` defaulting to TRUE. Use it only if a
page-image viewer is built first, and add a dry run before running it.

## Track limits

Tracks are `medical`, `nursing`, `dental` only (`backend/config/tracks.js`). Laboratory (SLLE) material has no
track, no `question_type` set and no summaries; adding one is a product decision (tracks mirror in
`my-react-app/src/utils/tracks.js`, `CHECK` constraint, pricing copy), not an import.
